# -_2



Учебное веб-приложение «CloudNotes» (сервис личных заметок) с намеренно внедрёнными уязвимостями из OWASP Top 10, скрипт их эксплуатации и патчи в формате `diff`.

> Внимание. Приложение специально содержит уязвимости. Запускайте его только локально (`127.0.0.1`) или в изолированной виртуальной машине. Не выставляйте в интернет и не применяйте методы из этого репозитория к чужим системам.

 Структура репозитория

| Файл | Описание |
|---|---|
| `app.py` | Итоговое приложение (с патчами) |
| `app_orig.py` | Исходное уязвимое приложение |
| `exploit.py` | Скрипт эксплуатации уязвимостей (Часть 2) |
| `fix_xss.patch` | Патч для Stored XSS |
| `fix_idor.patch` | Патч для IDOR |
| `fix_sqli.patch` | Патч для SQL-инъекции |
| `all_fixes.patch` | Все исправления одним файлом (от `app_orig.py` к `app.py`) |
| `report_part2.txt` | Результат эксплуатации на уязвимом приложении |
| `report_after_patch.txt` | Результат эксплуатации после патчей |

Требования

- Python 3.8 или новее
- Сторонние библиотеки не нужны: используются только стандартные модули (`http.server`, `sqlite3`, `urllib`, `re`, `html`)

 Описание приложения

Пользователь регистрируется, входит в систему и создаёт личные заметки. Заметки видны только владельцу (по задумке). В приложении есть:

- `/` — список заметок текущего пользователя;
- `/register`, `/login`, `/logout` — регистрация, вход и выход;
- `/new` — создание заметки;
- `/note?id=N` — просмотр заметки;
- `/search?q=...` — поиск заметок по заголовку.

Тестовые пользователи (создаются при запуске):

| Логин | Пароль |
|---|---|
| alice | alice123 |
| bob | bob456 |
| admin | SuperSecretAdminPass! |

Уязвимости

| № | Уязвимость | Категория OWASP | Где в коде (`app_orig.py`) |
|---|---|---|---|
| 1 | Небезопасные прямые ссылки на объекты (IDOR) | A01:2021 Broken Access Control | `view_note_detail`: заметка выбирается только по `id`, без проверки `user_id` |
| 2 | SQL-инъекция | A03:2021 Injection | `view_search`: запрос собран f-строкой из параметра `q` |
| 3 | Хранимая XSS (Stored XSS) | A03:2021 Injection | `view_index`, `view_note_detail`: заголовок и текст заметки выводятся без `html.escape` |

Дополнительно в исходной версии есть уязвимость A05:2021 (Security Misconfiguration): текст ошибки SQL показывается пользователю. Она исправляется необязательным шагом в `fix_sqli.patch`.

Запуск приложения

```bash
python3 app.py
```

Откройте в браузере: http://127.0.0.1:8000

При каждом запуске база данных `notes.db` пересоздаётся с тестовыми данными.

Остановка сервера: `Ctrl + C`.

 Часть 2. Эксплуатация

Запустите приложение в одном терминале, а в другом выполните:

```bash
python3 exploit.py | tee report_part2.txt
```

Скрипт последовательно выполняет три атаки:

1. IDOR. Без авторизации перебирает `id` заметок и читает чужие, включая заметку администратора с флагом `FLAG{idor_and_sqli_are_dangerous}`.
2. SQL-инъекция. Через поиск с `UNION SELECT` получает логины и пароли всех пользователей из таблицы `users`.
3. Stored XSS. Регистрирует временного пользователя, создаёт заметку с `<script>` в заголовке и проверяет, что скрипт сохранился без экранирования.

Результат уязвимого приложения сохранён в `report_part2.txt`.

 Часть 3. Патчи

Исправлены все три уязвимости:

| Уязвимость | Исправление | Патч |
|---|---|---|
| Stored XSS | Вывод заголовка и текста через `html.escape()` | `fix_xss.patch` |
| IDOR | Заметка ищется по `id` и `user_id = текущий пользователь` | `fix_idor.patch` |
| SQL-инъекция | Параметризованный запрос (`?`) и поиск только по своим заметкам | `fix_sqli.patch` |

Применить все исправления к исходному коду:

```bash
cp app_orig.py test_check.py
patch test_check.py < all_fixes.patch
```

После патчей повторный запуск `exploit.py` даёт такой результат (см. `report_after_patch.txt`):

- IDOR: чужие заметки не открываются, флаг не получен;
- SQL-инъекция: данные пользователей не извлекаются;
- XSS: скрипт выводится как текст, а не выполняется (`&lt;script&gt;`).

 Как проверить вручную

1. Запустите `app.py`.
2. Откройте http://127.0.0.1:8000/note?id=3 без входа: до патча заметка видна, после патча — «Заметка не найдена».
3. Введите в поиске `' OR 1=1 --`: до патча показываются все заметки, после патча поиск ничего не находит.
4. Создайте заметку с заголовком `<script>alert(1)</script>`: до патча появляется всплывающее окно, после патча отображается текст.

Выводы

В работе показано, как типовые ошибки разработки (конкатенация строк в SQL, отсутствие проверки владельца объекта, вывод пользовательских данных без экранирования) приводят к утечке данных и выполнению чужого кода. Исправления простые: параметризованные запросы, проверка прав на уровне запроса и экранирование при выводе в HTML.
